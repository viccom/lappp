# 上游同步记录模板

> 每次同步以本文件为模板，在仓库外另存为 `lap-sync-record-<syncId>.md`。只记录本次实际观察到的事实；未执行项写“未执行”，失败保留原始退出码与日志位置。不得记录密钥、令牌或其他凭据。

## 1. 冻结快照

| 字段 | SHA / 值 | 采集命令或说明 |
|---|---|---|
| 同步日期 / 操作者 | | |
| 当前分支 / 工作区 | | `git status --short --branch`；确认干净；不干净则停止，不删除或覆盖工作改动 |
| `develop` 基线 | | `git rev-parse develop` |
| 本地 `main` 基线（旧 SHA） | | `git rev-parse main`；只作基线，不得在门禁通过前快进 |
| 上游基线（同步窗口起点） | | fetch 前 `git rev-parse upstream/main`；优先核对上次记录的冻结目标 SHA，不一致时记录实际 SHA 并暂停评估 |
| 上游目标（冻结，不再跟随移动分支） | | `git rev-parse upstream/main`，fetch 后记录 |
| `develop` 与上游目标的 merge-base | | `git merge-base <develop base SHA> <upstream target SHA>` |
| 隔离工作树绝对路径 / 分支 | | 从冻结 `develop` SHA 创建；初始化子模块、在 worktree 内 frozen install；不得使用已有路径/分支；关闭未提交候选后仅移除工作树，记录仍保留的新建 `$syncBranch` 也要登记 |
| 候选基线 / `HEAD` / `MERGE_HEAD` | | 候选初始 `HEAD` 必须等于 `develop` 基线；merge 期间 `HEAD` / `MERGE_HEAD` 分别核对冻结 `develop` / upstream SHA；集成 commit 两个 parent SHA 顺序也须精确核对 |
| 外部同步记录绝对路径 / SHA-256 | | 先在仓库外写记录；仅获隔离集成 merge commit 单独授权后复制到候选，目标不得已存在；记录自身不构成提交授权 |
| 工作区状态 | | `git status --short --branch`；必须确认基线干净 |
| 上游来源 / fetch 时间 | | 只 fetch；核对 URL 为 `julyx10/lap`；仅记录不含凭据的仓库地址及时间 |

所有比较均使用以上完整 SHA，不用 `HEAD~1`、浮动分支名或版本标签代替冻结范围。

| 项目 | 记录 |
|---|---|

| 备份数据库绝对路径 / 文件名（创建前确认不存在） | |

备份脚本只快照一个 SQLite 数据库，不复制配置、sidecar、缩略图缓存或图片。不得把数据库备份误当成完整应用数据备份，也不要求用真实用户图库做测试。

## 5. 结论与授权边界

**集成结论：** GO / NO-GO。理由：

**剩余风险 / 未覆盖项：**

| 动作 | 本次是否获明确授权 | 授权者 / 消息位置 | 精确目标（分支与 SHA、路径或版本） | 执行结果 |
|---|---|---|---|---|
| 创建隔离集成 merge commit（含同步记录） | 否 / 是 | | | |
| 快进本地 `main` 到冻结 upstream SHA（门禁通过后单独授权） | 否 / 是 | | | |
| 快进 `develop` 到已验证 integration SHA | 否 / 是 | | | |
| 推送 `origin/main` | 否 / 是 | | | |
| 推送 `origin/develop` | 否 / 是 | | | |
| 隔离数据目录 GUI smoke | 否 / 是 | | | |
| 真实数据目录 GUI smoke | 否 / 是 | | | |
| 覆盖 `D:\LapPortable` | 否 / 是 | | | |
| 发布 / 对外分发 | 否 / 是 | | | |

授权不得从一个动作推定到其他动作。未获授权的提交、分支前进、推送、smoke、部署及发布均保持未执行。若未授权创建候选集成提交，最终记录保留在仓库外，须在此报告其精确绝对路径；不得为了归档另建提交。
