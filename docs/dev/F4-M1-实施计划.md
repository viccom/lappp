## 1. 每个小步的完成定义（统一规则）

一步算完成，必须同时满足：

1. **先红后绿**：新增测试先实际跑一次、看到它们因为功能缺失而失败，再写实现。（写完实现才补的测试，要临时撤掉实现确认它会红，并在报告里说明。）
2. **门禁**：`cargo test --workspace`（Rust 步）；`npm run test`、`npm run typecheck:gate`、`npm run test:crossrefs`、`npm run build`（前端步）。退出码自己看，不经管道。
3. **证据**：报告里贴 `test result:` 行与命令退出码，不写「应该通过」。
4. **一个提交**：提交信息写「改了什么、为什么」；只增不改上游行为，除 F4 §7.3 列出的适配点。
5. **回滚**：Rust 侧全是新文件或加几行，`git revert` 单提交即可；S4 含一次迁移（见下），回滚时要连迁移一起退。

**没有图谱表的库必须与现在完全一致**——这条从 S1 起每一步都要复验，不只 S4。

## 2. S1 · 模块骨架与按需建表

**目标**：`crates/lappp-core/src/t_household.rs` 存在且可用。

**做**
- `ensure_schema(conn)`：六张表的 `CREATE TABLE IF NOT EXISTS` + 表达式唯一索引（F4 §4.3），幂等。
- `tables_present(conn) -> bool`：只看 `sqlite_master` 里有没有 `household_nodes`。所有读路径先过它。
- 关系目录：`NodeClass`、`RelationType`（kind / label / from / to / direction / inverse_label / generative / time_scoped），`NODE_CLASSES`、`RELATION_TYPES` 两张常量表（F4 §4.6，社交标签六种：classmate / teacher / friend / colleague / neighbour / partner）。
- 校验与归一化：`is_known_kind`、`is_known_label`、`normalise_edge`（对称边按 id 小的在前、`teacher` 只存老师→学生）。

**不做**：命令、推导、卡渲染、任何界面。

**验收**（`cargo test -p lappp-core --lib t_household`）
- 空库 `tables_present` 为假；`ensure_schema` 之后为真且六张表都在；再调一次不报错。
- 目录外的 `kind` / 社交外的 `label` 被拒；两端对象类不符被拒。
- `spouse` 与对称 `social` 归一化后只存一条；`teacher` 反向输入归一成老师→学生。
- 同一对节点同一关系唯一（`COALESCE(label,'')` 表达式索引真的挡住第二次插入）。
- 既有 632 条测试（core）不变红，整个工作区仍是 720 通过。

**拒绝条件**：六张表被写进 `t_migration.rs` 的迁移链（D5 不是迁移）；任何命令提前注册。

## 3. S2 · 对象与边的写入面

**目标**：写库的函数都在，但还没接命令。

**做**
- `create_household_with_conn(conn, name, album_ids, root_node_name, import_names)`：一步建图 → 导入 → 设根（F4 §7.1 的约定）。
- `import_names_with_conn`：幂等；一个脸名已被别的对象锚定就只补成员关系，不建第二个对象；`Person N` 与非空名字的判定**复用** `t_sqlite::Person::is_automatic_name`（M0 定的唯一处，不要再写第二份）。
- `upsert_node_with_conn`（含锚点整批替换）、`set_members_with_conn`、`set_edges_with_conn`（整批替换 + 全量校验 + 一个事务）、`delete_household_with_conn`（只删分组，保留对象与边）、`delete_node_with_conn`（不能删任何图谱的根）。

**验收**（`cargo test -p lappp-core --lib t_household::write`）
- 导入幂等：同一个人导入两次，人物行与成员关系各一份。
- 一个脸名不能锚定到两个对象（第二次导入被挡）；`Person N` 不能做锚点；空名字不能做锚点。
- 根不能删；删图谱后对象与边还在。
- 整批替换是原子的：中途一条边非法 → 事务回滚，原来的边一条不少。
- 自环、`parent` 成环、有效期倒置、同一对节点同一关系重复 → 全被拒。
- 一个人可以同时属于两份图谱而不产生第二个对象。

**拒绝条件**：任何写函数逐条自动提交（必须一个事务）；绕过同一套校验。

## 4. S3 · 关系推导与年龄（纯函数）

**目标**：给定对象、边、根、拍摄年份，算出「A 是 B 的 ___」。

**做**
- `kinship(edges, nodes, a, b, year) -> Option<String>`：只在**当时成立**的 `parent` / `spouse` 上做最短路径（`suggested` 与 `social` 不参与），翻译成中文（F4 §4.4 全表）。
- `term_from_root(...)`：相对根的称呼（F4 §4.4.1、§4.4.2 覆盖清单）。
- `age_at(birth_date, taken_date) -> Option<i64>`：由程序算，模型不做减法。
- `term_override` 优先；推不出返回 `None`。

**验收**（`cargo test -p lappp-core --lib t_household::derive`，纯函数、不建库）
- 逐条覆盖 §7.4 清单：父/母、子/女、配偶、爷爷奶奶外公外婆、孙辈两侧、兄弟姐妹（有/无出生年）、伯伯与叔叔（**缺年份退化成「伯父或叔父」**）、姑姑、舅舅、姨母、堂表、岳父母/公婆、**儿媳/女婿**、**嫂子/弟媳/姐夫/妹夫**、孙媳/孙女婿。
- `social` 不进亲属推导（含 `partner`：恋人的父母不是岳父母）；同一年 `partner` 与 `spouse` 都成立时只写 `spouse`。
- 不可达 → `None`；`term_override` 生效；根为空时退化为边摘要。
- 有效期三种情形（尚未开始 / 成立 / 已结束）；已结束的配偶只写「前夫/前妻」，不参与其它推导。

**拒绝条件**：把推导写进 SQL；模型端推算任何关系。

## 5. S4 · 图谱卡与 `{family}`

**目标**：把图谱投影成一小段事实交给模型；没有图谱时提示词与现在**逐字节相同**。

**做**
- `render_card(conn, file_id) -> Option<String>`（纯函数，入参是取好的数据）：只列本张照片认出的人、只写在场两人之间的关系、年龄按拍摄日期算好、成年人不写年龄、`share_details` 关闭时不写出生地/备注、人脸数多于卡内人数时追加「画面里还有 N 个人身份未知」（F4 §5.1 全套规则）。
- `PromptContext` 加 `family: Option<String>`；`render_template` 的定长数组 36 → **37**；`prompt_context_with_conn` 里**先 `table_exists` 再**取卡（无表就整段跳过，一个字节都不动）。
- 内置模板：事实块加 `{family}`、共享规则改成条件措辞（有图谱时「关系与年龄以人物档案为准」，没有图谱时保持现在的措辞）——按 D4，**改文字要配一次迁移**：新增 `v33`，里面再调一次 `seed_vl_template_library`（M0 已定的策略：文字变了以新版本行到达，旧行不动，新版本继承用户关掉的开关）。
- 前端：`VL_PROMPT_PLACEHOLDERS` 36 → 37；17 个 locale 的 `vl.placeholders_hint` 加 `{family}`。

**验收**
- 卡渲染（`t_household::card`）：无图谱 → `None`；照片里没认出任何节点 → `None`；只列在场的人；年龄算对（拍摄年 − 出生年）；成年人无年龄；`Person N` 不出现；`suggested` 的边不出现；社交边出现。
- **逐字节回归**（最关键一条）：一个没有图谱表的库，`prompt_context_with_conn` 渲染结果与改动前**逐字节相等**（基线字符串写在测试里）。
- 模板迁移：`v32` 的库跑到 `v33` 后，内置模板多出新版本行；用户关掉的模板仍是关的；已有标注指向的旧版本行不动。
- `npm run test:locale`、`npm run test:crossrefs` 绿；占位符计数在 37 上。

**拒绝条件**：`{family}` 在没有图谱时输出一个空行或一句占位（必须整个字段为空、渲染成空串）；把卡拼进系统提示的固定文字里。
